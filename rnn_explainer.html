LSTM, GRU and TCN — a worked numerical walkthrough

Every number below is computed live from hand-designed weights. Edit the input sequence, scrub to any timestep, and watch the arithmetic.

The task

The simplest problem that actually needs memory: a latch. At each timestep the network sees one of three things.

InputEncodingMeaning
set[1, 0]Turn the memory ON and keep it on.
clear[0, 1]Turn the memory OFF.
hold[0, 0]Nothing happens. Whatever was remembered must survive.

The network must output ≈1 while ON and ≈0 while OFF. It is trivial for a human and impossible for a feed-forward network on its own, because the correct answer at step 12 can depend on something that happened at step 1. That gap is exactly what these architectures exist to bridge.

The weights here were set by hand, not trained, so the mechanism is visible rather than buried in a learned soup of numbers. A trained network would find different weights that do roughly the same thing.

What c(t) and h(t) actually are

An LSTM carries two vectors from one timestep to the next. Nearly every confusion about LSTMs comes from collapsing them into one idea, so it is worth being precise.

c(t) — the cell state

The long-term memory, and the thing that makes an LSTM an LSTM. It is never passed through a weight matrix. The only two things that ever happen to it are: multiply element-wise by the forget gate, and add the gated candidate.

c(t) = f(t) · c(t−1) + i(t) · g(t)

Because the only path from c(t−1) to c(t) is a multiply by f and an add, the gradient flowing backwards is multiplied by f each step. If the network learns f ≈ 1 for a channel, the gradient reaches back hundreds of steps essentially intact. This is the "constant error carousel", and it is the whole reason LSTMs beat vanilla RNNs.

c is internal. Nothing outside the cell ever reads it directly.

h(t) — the hidden state

The output, and also the short-term working memory. It is a filtered view of c(t): squashed into (−1, 1) by tanh, then masked by the output gate.

h(t) = o(t) · tanh(c(t))

h(t) is what the next layer sees, what the loss is computed on, and what gets fed back into all four gates at the next timestep. The split matters: the cell can hold a value for fifty steps while o keeps h(t) at zero the whole time, revealing it only when it becomes relevant.

In PyTorch, output is the sequence of h(t); (h_n, c_n) is the final pair.

Analogy that survives contact with the equations: c is the notebook, h is what you say out loud. The forget gate erases lines in the notebook, the input gate writes new ones, and the output gate decides how much of the notebook to read aloud this turn.

Notice what the trained-network version of this would look like: the same four numbers per gate, found by gradient descent instead of by hand, and totally unreadable. The mechanism is identical — σ producing keep-fractions, tanh producing candidate values, one multiply and one add on the cell state.

The GRU: same job, one state, two gates

A GRU deletes the cell state entirely. There is only h(t), and it is both the memory and the output. To make that work it merges the forget and input gates into a single update gate, and adds a reset gate that controls how much of the past the candidate is allowed to see.

h(t) is now the only state

h(t) = (1−z)·h(t−1) + z·h̃(t)

A convex blend. Whatever fraction of h(t−1) you keep is exactly the fraction of the candidate you don't take — one knob, not two. z ≈ 0 passes the old state through untouched, which is the additive skip path that keeps gradients alive. z ≈ 1 overwrites completely.

No output gate, so the full state is exposed every step. A GRU cannot hold something privately.

The reset gate is the subtle one

h̃(t) = tanh(W·x(t) + U·(r · h(t−1)))

r gates the history fed into the candidate, not the output. Setting r ≈ 0 lets the unit compute a fresh candidate as if the sequence were starting over — which is exactly how this network handles clear: reset the history to nothing, then overwrite with it.

This is why a GRU needs two gates rather than one: z alone can only interpolate towards the candidate, and the candidate itself is contaminated by the past unless r can cut it off.

Compare the parameter counts. For hidden size n and input size m: LSTM = 4·(n+m+1)·n, GRU = 3·(n+m+1)·n. That 25% is the entire practical difference most of the time — on ordinary regression and classification the two are statistically indistinguishable, and hyperparameter tuning matters far more than the choice between them.

The TCN: no state at all

A temporal convolutional network throws out recurrence. There is no h, no c, nothing carried from step to step. Instead it stacks dilated causal convolutions and lets depth buy history.

Causal

Pad only on the left by (k−1)·d, then truncate the right. The output at time t is then a function of inputs ≤ t and nothing else. For forecasting this is the constraint that stops the model quietly reading the future and looking brilliant in backtest.

Dilated

Layer i skips d_i = 2^i positions between taps. Receptive field is 1 + (k−1)·Σd_i, so it grows exponentially in depth. Three layers with k=2 reach back 8 steps; ten layers reach back 1,024.

Every timestep is computed in parallel — that is the speed advantage over an RNN, which must unroll sequentially. The cost is that memory is a hard window rather than a soft, in-principle-unbounded state.

The stack, with live values

Each unit takes two inputs — itself and the one d steps to its left — and keeps whichever carries the more recent instruction. Green = ON, red = OFF, grey = no instruction seen yet.

The demo block here is a simplified "keep the more recent instruction" operation rather than a literal weighted convolution, so the arithmetic stays readable. A real TCN residual block is: dilated causal conv → weight norm → ReLU → dropout, twice, plus a 1×1 conv on the skip path. It learns weights that approximate this kind of selection. The receptive-field arithmetic — the thing that actually matters when you size one — is exact.

Sizing one for real work

For 5-minute NEM dispatch data with kernel size 3, the receptive field is 2^(n+1) − 1 steps for n layers. Eight layers gives 511 steps ≈ 42 hours. You need ten for a full week. Compute this explicitly before training and check it covers the seasonality you care about — anything outside it is not "weakly remembered", it is structurally invisible.

Practical default: try the GRU first — fewer parameters, faster, one word's difference in PyTorch (nn.GRU vs nn.LSTM, returning (output, h_n) rather than (output, (h_n, c_n))). Reach for the LSTM when sequences run past ~200 steps, when you have plenty of data, or when the task needs precise state-machine behaviour — LSTMs are provably stronger than GRUs on formal-language benchmarks because the output gate lets them hold a value while concealing it.

Reach for the TCN when the series is long, regularly sampled, and you can name the horizon that matters. Size the receptive field deliberately, and remember that causal padding protects you inside the network but nothing protects you from a lagged feature or a scaler fit across the train/test boundary. That, not the architecture, is the most common silent bug in sequence forecasting code.
