Autoencoders, worked: plain, denoising, sparse, stacked

Every chart below comes from a small neural network that this page trains in your browser, from scratch, when it loads (about a second). The data are synthetic "days" of eight three-hourly NSW-style prices. Nothing is hard-coded; the random seed is fixed so the same numbers come back on every visit (change the seed in the script to re-roll).

1 · What an autoencoder is, and why anyone would train a network to output its own input

In one sentence. An autoencoder is two networks glued together, an encoder that squeezes the input into a few numbers and a decoder that rebuilds the input from those numbers, trained so that the rebuild matches the original; the few numbers in the middle are a learned summary, and the point of the whole exercise is to get that summary.

Suppose every day's price profile were secretly made from just two dials: a base level and an evening-peak height. If you knew the dials you could redraw the day. An autoencoder is a machine that discovers the dials from examples. The encoder learns "read the day, set the dials"; the decoder learns "read the dials, draw the day". Because the middle is narrow (two numbers for eight prices), the network cannot cheat by copying; it has to find the structure.

Eight inputs, a two-unit bottleneck, eight outputs. Training minimises the difference between the right-hand column and the left-hand column.

The training data this page generates

240 synthetic days. Each is built from three hidden factors plus a little noise, in A$/MWh at 00:00, 03:00, 06:00, 09:00, 12:00, 15:00, 18:00 and 21:00:

price = level × (1 − 0.15 × midday dip) + peak × [0,0,0,0,0,0.3,1,0.4] + morning × [0,0.2,1,0.5,0,0,0,0] + noise
level
A$40 to A$120, the overnight baseline
peak
A$0 to A$250, the evening peak height (the dominant factor)
morning
A$0 to A$30, a small breakfast bump (deliberately minor, to see what a 2-number bottleneck throws away)
noise

200 days are used for training and 40 are held out for testing. All prices are divided by 100 before they enter the network and multiplied by 100 on the way out.

2 · The plain autoencoder: 8 → 2 → 8

Encoder: one layer, 8 inputs to 2 units with a tanh bend. Decoder: one linear layer, 2 to 8. Loss: mean squared reconstruction error. Optimiser: Adam, 1,200 full-batch steps. That is 8×2 + 2 + 2×8 + 8 = 42 weights in total.

What did the two numbers learn to mean?

Ask the decoder directly: hold one code number at zero and sweep the other from −1 to +1, and draw what it produces. Each code number is a "dial" and its sweep is the shape that dial controls.

Dial 1 swept from −1 (light) to +1 (dark), dial 2 held at 0.
Dial 2 swept, dial 1 held at 0.
Every training day placed at its two code values. Colour is the true evening-peak height, size is the true base level. The network was never told either factor; it found axes that separate them because that is the cheapest way to rebuild the days.
Reading it
The dials are usually rotated or mixed versions of (level, peak) rather than the clean factors, because any rotation of the code plane reconstructs equally well; that is why autoencoder features are useful to a downstream model but rarely interpretable one by one.

What the bottleneck size does

Same setup, different middle widths. Fewer numbers, more loss; more numbers than there are real factors, and the network starts storing noise.

Common confusion. A linear autoencoder with k units learns the same subspace as principal component analysis (PCA) with k components. The nonlinearity (tanh) in the encoder is what lets it beat PCA on curved structure. On this nearly-linear toy the gap is small; on real price data with regime shifts it is not.

3 · The denoising autoencoder: train on damaged input, target the clean input

In one sentence. Corrupt each training day before it enters the encoder, but keep the loss against the uncorrupted day; the only way to succeed is to learn what typical days look like and use that knowledge to fill in the damage, so the code stops caring about noise.

Corruption used here, applied fresh every training step: Gaussian noise of A$12 on every slot, and with probability 0.3 one random slot gets a spurious spike of up to A$80 added, imitating a single-interval bid jump.

One day (grey), its corrupted version (red), and what the two autoencoders make of the corrupted version: plain (dashed purple) and denoising (solid green).
Reading it
On clean input both autoencoders are similar. On corrupted input the plain one passes part of the damage through (it was never taught that a spike at 09:00 is implausible), while the denoising one . Tan 2023 stacks denoising autoencoders on top of the CNN's features precisely so that the regression at the top sees features that have been made insensitive to interval-level jitter.
The denoising trick assumes the noise you add in training resembles the noise you will meet. It suppresses that kind of variation. If the "noise" is actually the signal you want (a genuine spike), a denoising front end will smooth it away, which is one reason decomposition-plus-autoencoder pipelines look good on average error and poor on spike windows.

4 · The sparse autoencoder: a wide middle, but only a few units allowed on

In one sentence. Give the middle layer more units than the input has values, which would let it copy the input straight through, then add a penalty on how much the units activate; the network is forced to explain each day with a few strongly-active units, and each unit ends up standing for one recognisable pattern.

Two ways to write the penalty. The classic one (used in the SSDAE literature Tan 2023 builds on) is a Kullback-Leibler term per hidden unit comparing its mean activation ρ̂j with a small target ρ:

KL penalty = β · Σj [ ρ log(ρ/ρ̂j) + (1−ρ) log((1−ρ)/(1−ρ̂j)) ]

The simpler one, which this page uses because it produces exact zeros you can see, is an L1 penalty on the activations themselves:

L1 penalty = β · Σj |aj|, with rectified (ReLU) hidden units so that "off" really means 0

Both say the same thing: activity is expensive, so use as little as possible. To give the network something discrete to be sparse about, this section uses a second synthetic dataset in which each day is a base level plus any combination of four on/off parts, each present with probability one half:

Model: 8 → 12 (leaky ReLU) → 8, trained twice with Adam for 3,000 steps: once with β = 0 and once with β = 0.008. The middle is wider than the input, so without the penalty the network is free to spread every day across all twelve units.

Reading it
That one-unit-per-pattern structure is the whole point: a downstream regression reading this code gets a short checklist ("evening peak present, solar dip present") instead of a scrambled mixture. In SSDAE the "sparse" is this penalty and the "denoising" is the corruption from section 3; both are applied at once, layer by layer.
How many units specialise depends on the random starting weights. Re-running this experiment with five different seeds gave 2 to 5 part-tracking units with the penalty and 2 to 3 without, with the penalty always cutting mean activation by four to six times. The seed used on this page is a typical good case, not the best of the five.
Common confusion. Sparse does not mean small. The sparse layer is usually wider than the input (over-complete); it is the activity, not the width, that is constrained. The plain bottleneck autoencoder of section 2 is the opposite trade: narrow and fully active.

5 · Stacking: train one layer at a time, then fine-tune the whole tower

In one sentence. Train autoencoder 1 on the data, freeze its encoder, train autoencoder 2 on the codes that encoder 1 produces, and so on; then discard the decoders, put a regression layer on top of the encoder tower, and train everything together on the real target; each stage starts from weights that already capture structure, instead of from random numbers.

  1. AE1: 8 → 4 → 8 on the days. Keep encoder E1 (8 → 4).
  2. Push every day through E1 to get 4-number codes. AE2: 4 → 2 → 4 on those codes. Keep encoder E2 (4 → 2).
  3. Stack: day → E1 → E2 → new linear layer → target. Here the target is tomorrow's evening peak, which is generated as 0.7 × today's peak + 0.3 × today's level + noise, so it is learnable but not trivial.
  4. Fine-tune all layers together on the target.
Greedy layer-wise pre-training, then supervised fine-tuning. The decoders are scaffolding and are thrown away.

Plain gradient descent, sigmoid units, no tricks (the 2010-era setting in which stacked autoencoders were introduced). Validation RMSE of the peak forecast against training steps.
Same network with Adam and tanh units (the modern default).
Reading it
Two lessons sit in that result. First, the pre-trained tower starts from weights that already describe the data, so it reaches a reasonable error in fewer steps; that speed-up was the original 2006-era selling point, when deep sigmoid networks trained with plain gradient descent often failed to train at all. Second, the pre-training objective is reconstruction, not the target: AE2 keeps whatever two numbers rebuild the four-number code best, which is not necessarily what predicts tomorrow's peak, so the final error can end up no better, or slightly worse, than training from scratch. With Adam, ReLU-style units and sensible initialisation the speed advantage mostly disappears too. Tan 2023's remark that the SSDAE "accelerates training time and convergence" should be read against that history; what still stands is that the encoder tower produces denoised, sparse features that a simple regression can use.

7 · How Tan 2023 wires it: CNN → SSDAE → regression, once per frequency component

One of the parallel branches in Tan's model (there is one per intrinsic mode function from ICEEMDAN). The autoencoder stack sits between feature extraction and prediction.
  1. The CNN slides its filters over the last few days of one IMF and produces feature maps; flattened, that is a vector of a few dozen numbers per day.
  2. A stacked sparse denoising autoencoder is pre-trained on those vectors exactly as in sections 3 to 5: corrupted in, clean out, few units on, one layer at a time.
  3. The decoders are discarded; a linear (or small dense) regression layer maps the top code to the 48 half-hourly values of tomorrow's IMF.
  4. The whole branch is fine-tuned on the day-ahead target; the branches' outputs are summed to give the price forecast.
The autoencoder is doing three jobs at once in that position: shrinking the CNN's output so the regression has few weights (less overfitting on five years of data), making it insensitive to interval jitter (denoising), and giving the regression a code where each entry is a recognisable pattern (sparse). None of those requires the autoencoder to be a good forecaster itself; it never sees tomorrow until the fine-tuning step.
